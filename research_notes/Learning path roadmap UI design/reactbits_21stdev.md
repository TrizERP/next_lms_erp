# Learning Path / Journey Roadmap UI — Component Sources on ReactBits & 21st.dev

Research scope: find real, linkable component examples on reactbits.dev and 21st.dev that could serve as a basis for a gamified, step-by-step "learning path" roadmap (winding path connecting sequential milestones, status colors for completed/current/locked). This is a shopping list, not a tutorial — browse the links directly.

## Direct answers to the key questions

### Does reactbits.dev have path/roadmap/timeline/journey-map components?

**Takeaway:** No. ReactBits.dev has no dedicated category or component for timelines, roadmaps, paths, journey maps, or connected-node graphs. Its taxonomy is strictly: Text Animations, Animations, Components, Backgrounds, Micro Interactions (~215+ components total). The single closest primitive is a generic **Stepper**, which is a linear step-progress widget, not a path/road visualization.

- Direct crawl of reactbits.dev's homepage shows exactly five top-level categories — Text Animations, Animations, Components, Backgrounds, Micro Interactions — with no timeline/path/roadmap/journey section. — [reactbits.dev](https://reactbits.dev/)
- The project's GitHub repo (DavidHDev/react-bits) confirms the same five-category taxonomy (Text Animations 33, Animations 38, Components 48, Micro 34, Backgrounds 63 = 215+ components), with category descriptions ("Cards, navigation, carousels and galleries" for Components) that contain no mention of timeline/path/roadmap/journey/node components. — [github.com/DavidHDev/react-bits](https://github.com/DavidHDev/react-bits)
- A ReactBits **Stepper** component exists (framer-motion dependency) and is mirrored on the 21st.dev marketplace under an account labeled `deleted_reactbits`, described as "a reusable, animated stepper component with smooth slide transitions, progress indicators, and customizable step content," with a minimalist aesthetic (clean lines, refined motion) — this is a linear numbered-step indicator, not a path/road graphic. — [21st.dev/@deleted_reactbits/components/stepper](https://21st.dev/@deleted_reactbits/components/stepper.md)
- Third-party catalogs of ReactBits' component list place "Stepper" under an "Interactive Elements" grouping alongside MagicButton, Magnet, and Dock, and "AnimatedList"/"Bento Grid" under "Lists & Layouts" — none of which are path/journey-shaped. (Secondary source, not a direct reactbits.dev page crawl — flagged as lower-confidence.) — [claudeskills.info catalog](https://claudeskills.info/skills/freshtechbro/claudedesignskills/animated-component-libraries/)

**Conclusion for reactbits.dev:** it supplies raw animation *primitives* (SVG draw-on effects, particle/beam effects, hover/scroll micro-interactions, a generic stepper) that a developer could compose into a custom path UI, but it ships no ready-made roadmap/journey-map component. Nothing to shop for here directly — only building blocks.

### Does 21st.dev have roadmap/timeline/step-path/journey-map/progress-tracker/connected-node components?

**Takeaway:** Yes, extensively. 21st.dev (a shadcn/Tailwind-convention community marketplace, installable via `npx shadcn@latest add <url>?api_key=...`) has dozens of entries across exactly the patterns requested: literal "Animated Roadmap" milestone-path components, orbital/radial node timelines, network-node graphs, animated SVG beam/path-drawing effects, and many stepper/timeline variants with completed/current/upcoming status states. All are shadcn-CLI installable, so directly usable in a Next.js + Tailwind + shadcn-style codebase (the lms_k12 frontend stack). See categorized list below for specific names/authors/links.

## Categorized shortlist (21st.dev)

### 1. Gamified roadmap / milestone path (closest literal match to the ask)
- **Animated Roadmap** (hero-section-5 / "Animated Hero Section", by Ravi Katiyar) — visualizes a series of milestones laid out on a path (positioned via top/left/right coordinates) over an optional background map image, with framer-motion scroll-triggered animations. Each milestone carries an `id`, `name`, and `status` of `complete` / `in-progress` / `pending` — i.e. exactly the completed/current/locked status model requested. Reusable for any number of milestones. — [21st.dev/@ravikatiyar162/components/hero-section-5](https://21st.dev/@ravikatiyar162/components/hero-section-5.md) / [animated-hero-section-2 variant](https://21st.dev/@ravikatiyar162/components/animated-hero-section-2.md)
- **Project Milestones** (ibrandify) — "an interactive React project milestone timeline with selectable stages and progress states"; tagged Milestone/Roadmap/Timeline/Project Management. Supports selectable stages (click-through), suited to a per-chapter milestone picker. — [21st.dev/@ibrandify/components/project-milestones](https://21st.dev/@ibrandify/components/project-milestones.md)
- **Upvotable Roadmap** (olewandowski1 / 7ovr) — a roadmap card with vote counts, status/category badges, and a progress bar for in-development items. Less "path" visually, more card-based, but has the clean status-badge + progress-bar visual language worth reusing. — [21st.dev/@olewandowski1/components/roadmap-3](https://21st.dev/@olewandowski1/components/roadmap-3.md)
- **Status Roadmap Board** (olewandowski1 / 7ovr / shadcnstore) — Planned / In-Progress / Shipped kanban-style columns with vote counts, progress bars, contributor avatars, shipped dates per card. Note: this is a Kanban board, not a winding path — included only because it's the best-matching "status-colored roadmap" pattern if a column layout is acceptable. — [21st.dev/@olewandowski1/components/roadmap-1](https://21st.dev/@olewandowski1/components/roadmap-1.md)
- **Roadmap Card** (Berat Berkay Gökdemir) — individual roadmap item card; useful as a building block alongside the above rather than a full path visualization. — [21st.dev/@beratberkayg/components/roadmap-card](https://21st.dev/@beratberkayg/components/roadmap-card.md)

### 2. Animated SVG path/line (for drawing the winding road itself)
- **Path Beam** (kevingirelli) — an animated SVG beam of light that travels along the paths of a flow diagram, lighting up each step as it arrives; can be triggered on scroll-into-view, tied to scroll position, or driven by an arbitrary progress value (0–100%) — directly suited to "light up the path as the learner progresses." — [21st.dev/@kevingirelli/components/path-beam](https://21st.dev/@kevingirelli/components/path-beam.md)
- **Light Runner Path** (1haim) — draws an SVG path as a glowing fiber with a bulb-shaped head and tapering tail; tips at chosen positions merge into the stroke and flare when the runner passes them — a strong visual metaphor for "current step glowing as the student moves along the road." — [21st.dev/@1haim/components/light-runner-path](https://21st.dev/@1haim/components/light-runner-path.md)
- **Animated Beams** (dev.yadhakim) — glowing animated beams that travel along auto-calculated SVG paths between arbitrary DOM elements, with configurable curvature; useful for connecting milestone nodes without hand-authoring the curve. — [21st.dev/@dev.yadhakim/components/animated-beams](https://21st.dev/@dev.yadhakim/components/animated-beams.md)
- **Draw SVG** (phucbm) — generic SVG path line-drawing animation (the path "draws itself" on load/scroll) — a base primitive for animating the road's reveal. — [21st.dev/@phucbm/components/draw-svg](https://21st.dev/@phucbm/components/draw-svg.md)

### 3. Node-graph / connected-dots (orbital & network styles)
- **Radial Orbital Timeline** (jatin-yadav05; also listed under pathtoreisliencebv234 and jsnmhbl) — nodes arranged in a circular/orbital pattern around a central hub; each node carries a title, status, and an "energy level" value; keyboard-accessible nodes with expandable detail panels. Visually distinctive (orbital rather than linear) but a non-standard metaphor for a sequential K-12 path unless re-skinned. MIT license, lucide-react dependency. — [21st.dev/@jatin-yadav05/components/radial-orbital-timeline](https://21st.dev/@jatin-yadav05/components/radial-orbital-timeline) / [live demo](https://21st.dev/community/components/jatin-yadav05/radial-orbital-timeline/default)
- **Orbit Timeline** (fransederr) — a second, similarly-styled orbital timeline variant. — [21st.dev/@fransederr/components/orbit-timeline](https://21st.dev/@fransederr/components/orbit-timeline.md)
- **Nodes** (abhishek-mallick) — an animated isometric network diagram: a hub plus eight nodes, where a pulse travels the shortest route to whichever node the pointer is nearest. Isometric/3D-tilted look; `@isometric` dependency, MIT license. Good reference for a "3D tilted map" treatment of a learning path. — [21st.dev/@abhishek-mallick/components/nodes](https://21st.dev/@abhishek-mallick/components/nodes.md)
- **Network Topology** (Mohammad Shehadeh) — lays out nodes (servers/gateways/etc. in the original use case) with status dots and icons, connected by animated SVG edges that visually distinguish active / idle / down links — directly maps to completed/current/locked node states on connecting edges rather than just the nodes. — [21st.dev/@mohammadshehadeh/components/network-topology](https://21st.dev/@mohammadshehadeh/components/network-topology.md)

### 4. Flat vertical/horizontal timeline (simpler, non-game baseline)
- **Timeline** (Aceternity UI, Manu Arora) — sticky header with a "scroll beam" that follows the user down a vertical timeline as they scroll; widely used reference implementation. — [21st.dev/@manuarora700/components/timeline](https://21st.dev/@manuarora700/components/timeline.md)
- **Timeline** (HextaUI, Preet Suthar) — flexible timeline for chronological events/processes/workflows; explicitly supports multiple orientations (vertical/horizontal) and per-item status plus custom content — the most directly reusable for a per-chapter status timeline. — [21st.dev/@preetsuthar17/components/timeline](https://21st.dev/@preetsuthar17/components/timeline.md)
- **Timeline** (ReUI, Sean Hello) — vertical or horizontal timeline for sequences of dated events/steps/milestones with connected indicators and separators. — [21st.dev/@sean0205/components/timeline](https://21st.dev/@sean0205/components/timeline.md)
- **Timeline Component** (Sam Siavoshian) — a modern glassmorphism-styled timeline marketed explicitly for "roadmaps, product launches, or history sections." — [21st.dev/@samsiavoshian2009/components/timeline-component](https://21st.dev/@samsiavoshian2009/components/timeline-component.md)

### 5. Stepper / step-path with completed-current-locked states
- **Stepper** (kevingirelli) — accessible multi-step progress indicator for flows like checkout/onboarding; explicitly tracks which steps are complete, current, or upcoming, with optional clickable triggers per step (maps directly onto "locked" steps simply being non-clickable). — [21st.dev/@kevingirelli/components/stepper](https://21st.dev/@kevingirelli/components/stepper.md)
- **Animated Progress Stepper** (ShadcnSpace) — spring-animated progress line, a traveling dot that moves along the connector, a pulsing badge on the active step, and icon-to-checkmark morph on completion. The most "alive"-feeling stepper found; closest to a game-like feedback moment for completing a step. — [21st.dev/@shadcnspace/components/stepper-03](https://21st.dev/@shadcnspace/components/stepper-03.md)
- **Tron Stepper** (thegridcn) — numbered stages with connector lines styled with a neon Tron-inspired look; good reference for a high-contrast "current step glows" visual treatment. — [21st.dev/@thegridcn/components/stepper](https://21st.dev/@thegridcn/components/stepper.md)
- **Stepper** (kanchanasw) — numbered step indicator drawn with hand-drawn-style circles and connecting lines; a more playful/illustrated line style, which fits a K-12 gamified aesthetic better than a clinical corporate stepper. — [21st.dev/@kanchanasw/components/stepper](https://21st.dev/@kanchanasw/components/stepper.md)
- **Matte Steps Navigation** (sltowl) — numbered circular markers with a connector line that visually *fills* as steps are completed, plus back/continue controls — a clean reference for the "fill-in" progress-line interaction. — [21st.dev/@sltowl/components/matte-steps-navigation](https://21st.dev/@sltowl/components/matte-steps-navigation.md)

## Inferences

- 21st.dev is the far richer hunting ground for this specific UI pattern: because it's a crowdsourced marketplace layered on shadcn/Tailwind conventions, "roadmap," "timeline," "stepper," and "path" are all independently popular submission categories with 10+ entries each, whereas ReactBits is a curated, much smaller (~215-component) library focused on generic animation primitives rather than composed UI patterns.
- For a K-12 "winding road" visualization specifically, no single found component is a drop-in match. The most promising combination is: use **Path Beam** or **Light Runner Path** (or **Animated Beams**) to draw/animate the actual curved road/SVG path, place milestone nodes along it using the status model from **Animated Roadmap** (complete/in-progress/pending) or **Stepper** (complete/current/upcoming/clickable-vs-not), and borrow the fill/traveling-dot interaction from **Animated Progress Stepper** or **Matte Steps Navigation** for the "walking along the path" feel.
- All 21st.dev components require a 21st API key and are installed via `npx shadcn@latest add "<component-url>?api_key=$API_KEY_21ST"`, confirming they are shadcn-CLI-native and directly draggable into a Next.js + Tailwind + shadcn-style codebase (matching the lms_k12 frontend stack) with no framework adaptation needed, modulo each component's own listed npm dependency (commonly framer-motion, lucide-react, or radix-ui).

## Gaps

- I could not directly render/screenshot any of these components (WebFetch only returns markdown/text extraction, not visual rendering), so "what it looks like" descriptions above are drawn from each component's own listed description/metadata rather than first-hand visual inspection. A developer should open the live preview URLs directly before committing to one.
- reactbits.dev's live site appears to be a JS-rendered SPA; a direct crawl of `/components` returned 404 and the homepage crawl surfaced only top-level nav categories, not the full component grid. I relied on the GitHub source repo (DavidHDev/react-bits) as the authoritative list of categories/counts, which is likely accurate since it is the project's own repository, but I could not independently re-verify every one of its 215+ component names one-by-one within the tool-call budget.
- Whether the ReactBits "Stepper" is literally a current, native reactbits.dev page (vs. a possibly-stale `deleted_reactbits` listing on 21st.dev from an account that has since been removed/renamed) is unconfirmed — flagged as lower confidence above.
- I did not find any 21st.dev component explicitly named or tagged "journey map" on 21st.dev itself (a `site:21st.dev "journey map"` search returned zero on-domain hits); the one "journey map"-named block that does exist (shadcn.io's "Stepper Journey Map") is on a different, unaffiliated site, noted separately above.
