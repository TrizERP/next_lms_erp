# Charting seven styles for a learning path

Research across Dribbble, Pinterest, ReactBits, 21st.dev, isometric/3D design resources, and YouTube surfaces **six distinct visual-style families** for a K-12 gamified learning-path roadmap, plus a sharp asymmetry at the component level: ReactBits ships **zero** path/roadmap/journey components among its ~215+ animation primitives, while 21st.dev hosts **dozens** of installable shadcn-style entries that match the completed/current/locked brief almost literally, including one literally named "Animated Roadmap" with a `complete`/`in-progress`/`pending` status model ([21st.dev/@ravikatiyar162/components/hero-section-5](https://21st.dev/@ravikatiyar162/components/hero-section-5.md)). The strongest and most proven reference remains Duolingo's own winding-node path, which is extensively documented, has triggered real design debate (a claimed **40% engagement surge** per one growth newsletter against a widely-read backlash critique), and — unusually for a proprietary pattern — exists as multiple runnable open-source clones a developer can read line-by-line rather than reverse-engineer from screenshots. A dedicated "3D isometric learning path" product, by contrast, essentially does not exist as a named, citable case study; that look has to be assembled from general isometric-illustration technique plus a path component, borrowing more from game level-select map design than from anything education-specific. What follows is a browsable shopping list, not a single verdict: each section below is a different visual direction with its own tone, technical cost, and fit, so the right next step is to open several of these links side by side before committing to one.

## Duolingo's winding path is the proven template, and it's the only one you can clone wholesale

The vertical S-curve of circular lesson nodes is Duolingo's own documented design: the company describes its home screen as "a path that you'll follow step by step," where each circle equals one crown level and stories are folded into the path itself rather than living in a separate tab ([Duolingo blog](https://blog.duolingo.com/new-duolingo-home-screen-design/)). The pattern is popular enough to have escaped its origin product and become a named genre — Dribbble shots are explicitly tagged "Duolingo-style" even when applied to unrelated subjects, such as a competitive-exam ed-tech app ([Dribbble: Duolingo-style education app for competitive exams](https://dribbble.com/shots/24672857-Duolingo-style-education-app-for-competitive-exams)) or a general "Inspired by Duolingo App" series ([Dribbble: Educational App Part 3](https://dribbble.com/shots/25249861-Educational-App-Part-3-Inspired-by-Duolingo-App)). For browsing the style at the source, the official design-system shots by Jack Morgan for Duolingo define the bubble/line/color conventions directly ([Duolingo Design Guidelines](https://dribbble.com/shots/4029434-Duolingo-Design-Guidelines)), and two Figr Design recreations rebuild the actual path screens as a customizable base: [Make Duolingo UI your own](https://dribbble.com/shots/25616971-Make-Duolingo-UI-your-own) and [Duolingo Mobile UI (Recreated)](https://dribbble.com/shots/22423503-Duolingo-Mobile-UI-Recreated). A more dimensional, glossier take appears in [Duolingo mobile app redesign – 3d playful clean UI](https://dribbble.com/shots/16768109-Duolingo-mobile-app-redesign-3d-playful-clean-UI), and Pinterest offers browse-more depth via boards like [73 Duolingo Ui ideas](https://in.pinterest.com/imtndragon/duolingo-ui/).

What makes this category uniquely actionable is that the pattern isn't locked behind proprietary code. Two full open-source clones are live and inspectable: a React/TypeScript/Next.js/Tailwind/Zustand build with a working deployed demo ([GitHub: bryanjenningz/react-duolingo](https://github.com/bryanjenningz/react-duolingo), [live demo](https://react-duolingo-clone.vercel.app/)), and a second, more full-featured clone with an admin dashboard, Stripe premium tier, and Google SSO built on Next.js/ShadCN/Drizzle/Neon ([GitHub: RikhiSingh/Duolingo-Clone](https://github.com/RikhiSingh/Duolingo-Clone)). On video, "Stop Making Ugly Apps. Use This Duolingo UI Kit Instead." is framed specifically as a design-breakdown/reuse video rather than a from-scratch build, making it the fastest way to see the visual pattern explained ([YouTube](https://www.youtube.com/watch?v=1Y3mZTyqhpw)); longer full-stack build-alongs that include the path screen as one part of a larger SaaS clone include ["From Zero to Duolingo Clone"](https://www.youtube.com/watch?v=K-_EqSy-pgI) and a SwiftUI-native series starting with ["Building Duolingo App in SwiftUI, Part 1"](https://www.youtube.com/watch?v=vhd31GeHcFc). It's worth knowing before committing to this direction that the pattern is contested, not universally loved: a widely-read UX critique argues the path redesign stripped out the old tree-style choice navigation and forced a single linear sequence, which "drove significant user backlash" despite the visual polish ([uxdesign.cc: "Down the Wrong Path"](https://uxdesign.cc/down-the-wrong-path-the-disaster-of-the-latest-duolingo-ui-update-a4cdd1e6ea1c)), even as a separate growth-newsletter case study credits the same redesign with a **40% engagement surge** ([Designfolio Substack](https://designfolio.substack.com/p/crazy-ux-redesign-duolingo)) — two sources in tension, flagged here rather than resolved, since the second is a single secondary claim.

## Flat-vector dashboards trade the game feel for editorial, in-product polish

A quieter sibling style drops the full-screen game map in favor of a path or arc that lives inside a conventional dashboard, paired with progress stats and course cards rather than a winding road taking up the whole screen. This is the style of real, shipped ed-tech products rather than game-adjacent concepts: Platzi's own student-home redesign introduces its "Learning Paths" concept this way ([New home for students at Platzi – Part 1](https://dribbble.com/shots/7561985-New-home-for-students-at-Platzi-Part-1-Learning-Paths)), and language-learning platform Mondly's dashboard shows the same editorial treatment applied to a competitor-adjacent product ([Mondly – UX/UI Dashboard Design](https://dribbble.com/shots/23949154-Mondly-UX-UI-Dashboard-Design-for-Language-Learning-Platform)). Joel Rosen's multi-layout exploration for Briefbox is useful specifically because it shows several variants of the same learning-path concept in one shot, functioning as a mini style-comparison on its own ([Learning Path UI layouts](https://dribbble.com/shots/3594217-Learning-Path-UI-layouts)). For a version that re-injects game mechanics without going full world-map, ["Gamified Learning Dashboard – XP, Quests, Rewards UI"](https://dribbble.com/shots/25971302-Gamified-Learning-Dashboard-XP-Quests-Rewards-UI) combines the path/progress metaphor with XP, quest, and reward patterns — a middle ground between this category and the Duolingo-style one above. Dribbble's own tags keep this browsable past the four picks here: [Learning Pathways](https://dribbble.com/tags/learning_pathways) and [Learning Paths](https://dribbble.com/tags/learning_paths).

## Game-world maps and isometric 3D fill the terrain depth that education design hasn't claimed for itself

Game level-select screens are a well-documented genre in their own right, and their structural requirements map almost one-to-one onto a K-12 roadmap's needs. An indie-dev devlog on redesigning a level-select screen states the spec plainly: "displaying level groups as nodes connected through a path in a landscape," with per-level locked/unlocked states and stats on the selected node — effectively a ready-made requirements document for this exact UI ([itch.io devlog: "Designing a Level Select Interface"](https://feitizogames.itch.io/geodessey/devlog/56371/designing-a-level-select-interface)), backed by an implementation-level tutorial on the same pattern ([GameDev.net: HTML5 Level Selection Screen](https://gamedev.net/news/2162-build-a-highly-customizable-mobile-friendly-html5-level-selection-screen/)). The visual references are strong and varied: a green terrain map threading level nodes through plains, hills, and windmill camps with depth-gradient coloring ([Game level map by BLINK](https://dribbble.com/shots/6278889-Game-level-map)), a high-saturation candy-themed stage-select map that reads as a strong tonal fit for younger K-12 audiences ([Candy Game UI – Map/Stage/Level Select](https://dribbble.com/shots/24010815-Candy-Game-UI-Map-Stage-Level-Select)), a multi-world structure useful if the curriculum needs grouped chapter "worlds" ([Game Level Map With 5 Different Worlds](https://dribbble.com/shots/3524199-Game-Level-Map-With-5-Different-Worlds)), and an animated version worth studying specifically for node-to-node transition behavior ([Mobile Game – Map UI Animation](https://dribbble.com/shots/3335723-Mobile-Game-Map-UI-Animation)).

Isometric/3D treatments, by contrast, are the thinnest category in this entire research effort: no named, citable "isometric learning-path" product surfaced despite multiple targeted search attempts. What exists instead is general isometric illustration applied to education loosely — a "Learning" isometric shot ([Learning – line isometric illustration](https://dribbble.com/shots/13374331-Learning-line-isometric-illustration)), a roadmap-titled shot that surfaced against isometric/game-roadmap queries ([Roadmap by NickZag](https://dribbble.com/shots/4366807-Roadmap)), and stock templates rather than product case studies, such as Adobe Stock's "3D isometric" course-selection onboarding set ([Adobe Stock: Online Course UI Template](https://stock.adobe.com/images/mobile-application-design-template-set-for-online-course-select-course-and-start-learning-ui-on-boarding-screens-design-concept-3d-isometric-modern-vector-illustrations-for-user-interface/397892813)). The practical implication is that this direction is a build-it-yourself proposition: Toptal's isometric-illustration tutorial covers the general technique of making 2D figures read as 3D, explicitly noting isometric graphics are common for bird's-eye-view process diagrams ([Toptal: Isometric Illustration Tutorial](https://www.toptal.com/designers/graphic/isometric-illustration-tutorial)), and a 4-week Blender course exists for anyone wanting to produce custom isometric roadmap art from scratch ([course.careers: Isometric Room Design in Blender 3](https://course.careers/graphic-design-courses/mastering-the-art-of-isometric-room-design-in-blender-3-course)). The more direct shortcut is to treat the game-world-map references above as the isometric/3D depth source instead, re-skinning a game overworld rather than hunting for an education-specific isometric case study that doesn't appear to exist yet.

## Timeline, stepper, and card roadmaps are real patterns worth knowing, but they drop the winding-road metaphor entirely

Two more styles turn up constantly under "roadmap" searches but satisfy only part of the brief: they deliver sequential milestones and status coloring without any winding road. The vertical timeline/stepper style — numbered circular markers on a straight connecting line, each paired with an icon and description — appears in a clean redesign-process section ([Steps / Roadmap Section](https://dribbble.com/shots/23726304-Steps-Roadmap-Section-UI-UX-Redesign-Process)) and a free, reusable component set ([Roadmap UI Design (Freebie)](https://dribbble.com/shots/19831308-Roadmap-UI-Design-Freebie)). The card-based style goes further still, abandoning a connecting line altogether in favor of a Kanban-style grid — Productboard's own feature-roadmap cards are the most "enterprise-polished" example in this entire research set ([Roadmap Feature Cards](https://dribbble.com/shots/14780471--Roadmap-Feature-Cards)), alongside a course-content card grid that treats sequencing as layout order rather than a visible path ([Course Cards](https://dribbble.com/shots/6246423-Course-Cards)). Both styles are included here deliberately as a way to rule them out quickly: they're common enough to keep surfacing in any "roadmap UI" search, but neither delivers the literal road the brief asks for, so they're best treated as a fallback only if the winding-path styles above turn out to be too illustration-heavy for the build budget.

## 21st.dev ships installable path components; ReactBits only ships the raw primitives

At the component-library level, the two named sources diverge sharply. ReactBits.dev's entire taxonomy is five categories — Text Animations, Animations, Components, Backgrounds, Micro Interactions, roughly 215+ components total per its own GitHub source — with no timeline, roadmap, path, or journey-map category anywhere in it; the closest thing is a generic linear **Stepper** widget, not a road visualization ([github.com/DavidHDev/react-bits](https://github.com/DavidHDev/react-bits)). It supplies only raw ingredients — SVG draw-on effects, particle/beam effects, hover micro-interactions — that a developer would have to compose into a path UI from scratch, not a ready component.

21st.dev is the opposite: a crowdsourced shadcn/Tailwind marketplace where "roadmap," "timeline," "stepper," and "path" are each independently popular submission categories with ten-plus entries, every one installable directly via the shadcn CLI into a Next.js/Tailwind codebase. The closest literal match to the brief is **Animated Roadmap**, which lays out milestones along a path over an optional background map with a `complete`/`in-progress`/`pending` status model per node — exactly the completed/current/locked semantics requested ([21st.dev/@ravikatiyar162/components/hero-section-5](https://21st.dev/@ravikatiyar162/components/hero-section-5.md)), alongside **Project Milestones**, which adds click-through selectable stages suited to a per-chapter picker ([21st.dev/@ibrandify/components/project-milestones](https://21st.dev/@ibrandify/components/project-milestones.md)). For drawing the road itself as an animated SVG line rather than a static graphic, **Light Runner Path** renders a glowing fiber with a bulb head that flares as it passes each stop — a strong metaphor for "the current step glows as the student advances" ([21st.dev/@1haim/components/light-runner-path](https://21st.dev/@1haim/components/light-runner-path.md)), and **Path Beam** offers the same idea driven explicitly by a 0–100% progress value, which maps directly onto percent-through-the-chapter progress ([21st.dev/@kevingirelli/components/path-beam](https://21st.dev/@kevingirelli/components/path-beam.md)). For a node-graph treatment with a 3D-tilted feel instead of a flat ribbon, **Nodes** is an isometric network diagram where a pulse travels the shortest route to the nearest node under the pointer ([21st.dev/@abhishek-mallick/components/nodes](https://21st.dev/@abhishek-mallick/components/nodes.md)), and for the simplest possible baseline, the HextaUI **Timeline** explicitly supports both orientations plus per-item status and custom content, making it the most directly reusable flat fallback if the full path proves too costly to build first ([21st.dev/@preetsuthar17/components/timeline](https://21st.dev/@preetsuthar17/components/timeline.md)). One adjacent find worth a direct look even though it sits outside these two named sites: a separate shadcn-blocks directory lists a component literally titled "Stepper Journey Map" ([shadcn.io/blocks/stepper-journey-map](https://www.shadcn.io/blocks/stepper-journey-map)) — not verified in depth here since it's off-brief, but its name alone makes it worth the five minutes to check.

## Conclusion

The practical path forward isn't to pick one category but to shop across two layers at once: a *visual style* (from the six families above — Duolingo-style winding path, flat-vector dashboard, game-world map, isometric/3D, timeline/stepper, or card grid) and a *technical base* (21st.dev's installable components, since ReactBits has nothing purpose-built here). The strongest combination that emerged from this research is compositional rather than any single find: use an animated SVG-path component like Light Runner Path or Path Beam to draw and progressively light the road itself, place milestone nodes along it using Animated Roadmap's complete/in-progress/pending status model, and borrow the game level-select devlog's explicit requirement list (nodes, connecting path, lock state, per-node stats, back/play controls) as the functional spec regardless of which visual skin wins. The one real caution surfaced in this research is strategic, not visual: Duolingo's own path redesign is simultaneously the most-cloned, best-documented reference available and a design decision that drew public backlash for removing navigational choice — so whichever style is chosen, it's worth deciding early whether the K-12 product wants a strictly linear path (easiest to build, closest to Duolingo) or something that preserves branching choice within the road metaphor, since that product decision will shape which of today's component building blocks actually fit.
